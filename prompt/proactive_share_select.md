你刚做完一次搜索，下面是原始结果。从里面挑**最适合分享给对方**的一条。

## 输入字段

- `platform`：xhs / bili / web
- `query`：你之前拟的搜索词
- `user_persona`：对方画像简介（兴趣、最近话题）
- `recent_topics`：对方近期聊过的话题
- `results`：搜索原始字符串（含 1-5 条候选；每条带标题、可能带赞数/播放量、链接）

## 怎么挑

挑一条**真的会戳到对方**的——不是最热的、不是最像广告的。判断标准：

- **跟 recent_topics 真有关联**优先（不是泛泛"也算这个领域"）
- **标题本身有信息密度 / 钩子**（"和 AI 恋爱三个月后和平分手了"比"AI 恋爱测评"好）
- **不是营销/带货/标题党**（"震惊"、"必看"、"教程"、"攻略大全"少选）
- **不是同一个老掉牙话题**（recent_topics 里已经聊深的方向，挑新角度的）

如果**所有候选都很无聊 / 都跟对方画像不搭**，宁可 give up（输出 `{"idx": -1}`）让上游降级到 topic_chat——别硬挑一个交差。

## blurb 写法

`blurb` 是 ≤30 字的**为什么这条戳**——不是标题复述，是你判断对方为什么会有兴趣。
后续 opener 生成会用 blurb 当生成依据。

✅ 好 blurb：
- "她聊过想学 hiphop，这个 up 主切片是入门最直观的"
- "她最近说被工作逼疯，这条吐槽设计师工作流的挺解压"
- "她提过『和 AI 恋爱』这个梗，这条分手帖是真有故事感"

❌ 差 blurb：
- "热度高赞数多" —— 只看数据没看 fit
- "跟兴趣相关" —— 太模糊
- 直接复述标题

## 输出格式

输出严格 JSON：
{
  "idx": 0,                              // 第几条（从 0 开始）；没合适的填 -1
  "title": "你挑的标题原文",
  "url": "https://...",
  "blurb": "≤30 字的'为什么戳到对方'"
}

idx=-1 时 title/url/blurb 全部留空字符串。
JSON 之外不要输出任何内容。
