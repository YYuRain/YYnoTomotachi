## 一、横向：开源框架对比

### 速查表

| 项目 | 2026-05 实测核心思路 | AIDemo 已对齐 | 可借鉴 | 不直接抄 |
|------|---------------------|--------------|-------|---------|
| **Mem0 v3** | **Single-pass ADD-only** + 实体抽取 + multi-signal retrieval (semantic+BM25+entity) + temporal reasoning | 抽取入库 | hybrid retrieval 三路融合；entity linking；放弃复杂写入决策 | 不分 user/session/agent 三层 scope |
| **Letta** | `memory_blocks` (label+value 常驻 prompt) + agent function-call 自管 archival/recall | 抽取 + 召回 | "memory_blocks" 命名 ≈ 我们 persona snapshot，可正式化 | 全量 function-call 自改记忆对小项目过重 |
| **Graphiti / Zep** | bi-temporal context graph：facts 有 validity window（invalidated 不删）；episodes 做 provenance；hybrid (semantic+BM25+graph) | 类似 5.1 冲突检测、`status/depends_on` | **validity window**（valid_from/valid_to） + **episodes 做 provenance** + Pydantic 定义实体类型 | 全图谱建模过重；陪伴关系密度不够支撑 graph traversal 收益 |
| **Cognee** | memory control plane；ECL pipeline；prescribed + learned ontology；audit traits/OTEL | 抽取 pipeline | OTEL 可观测 + 用户/租户隔离 trace | 控制面架构对单实例 bot 过重 |
| **LangMem** | 显式分 **hot path tool**（agent 自调 manage/search_memory_tool）+ **background manager**（自动 extract+consolidate+update） | 异步 5.1、同步 5.2、Auto Dream | "hot path vs background" 命名直接拿来文档化两条路径 | LangGraph stack 绑定 |
| **OpenAI Memory** | NL fact list；用户可见、可删、可关 | admin UI 已接近 | 用户 facing 的"saved memory" vs "chat history" 分层呈现 | 闭源 |
| **Anthropic Memory tool** | 让 model 主动 read/write 自己 memory 的 tool API | 自动写入 | 可选 LLM-driven 写入路径作为补充 | 平台特性 |

### 各项目要点（基于实拉 README）

#### Mem0 v3（2026-04，重点关注）

README 原文（已抓取）：

> **What changed in April 2026:**
> - **Single-pass ADD-only extraction** — one LLM call, no UPDATE/DELETE. Memories accumulate; nothing is overwritten.
> - **Agent-generated facts are first-class** — when an agent confirms an action, that information is now stored with equal weight.
> - **Entity linking** — entities are extracted, embedded, and linked across memories for retrieval boosting.
> - **Multi-signal retrieval** — semantic, BM25 keyword, and entity matching scored in parallel and fused.
> - **Temporal Reasoning** — time-aware retrieval that ranks the right dated instance for queries about current state, past events, and upcoming plans.

Benchmark：LoCoMo 71.4 → **91.6**（+20）；LongMemEval 67.8 → **94.8**（+27，assistant memory recall +53.6）。

**对 AIDemo 的强反转启示**：v3 的核心论点是"复杂的写入决策（v2 的 ADD/UPDATE/DELETE）解决的是错的问题——靠强检索就行"。这跟 AIDemo 的 PRD v2 三层防线方向**部分对立**：我们花大量 LLM 算力做 5.1/5.2/5.3，本质上是在写入侧消除噪声。Mem0 v3 用实测说：与其消除噪声，不如让 retrieval 更聪明（BM25 + entity boost + 时间感）。

但**不该全盘照抄**：(1) 我们做的是陪伴而非 task agent，"用户曾经-现在的演化叙事"本身就是产品价值，stale 标记是有意义的；(2) Mem0 benchmark 是 QA 任务，AIDemo 的成功度量是"她记得我"的情感对齐，未必能搬基准；(3) ADD-only 长期会让 admin UI 列表爆炸，admin 心理负担大。

**真正可学**：用 v3 的 hybrid retrieval（semantic + BM25 + entity）替换我们当前的"cosine + 双门"。陪伴语境里"那个我提过的播客叫啥来着"这种召回，pgvector 单路确实弱。pg 自带 `ts_vector` 做 BM25 + 自己抽 entity 表 index 工程量都不大。

#### Letta（前 MemGPT）

README 现状（实拉）：API 上明确是 `memory_blocks: [{label: "human", value: "..."}, {label: "persona", value: "..."}]`，agent 通过 `tools` 调用 `web_search/fetch_webpage` 等。memory_blocks 常驻 system prompt，agent 用 `core_memory_replace/append` 工具自改。

**对 AIDemo**：persona snapshot 表（traits/mood/observations/milestones）就是"per-user memory_blocks"，但我们没把它命名为"core memory"，前后端术语不统一。命名一统会让架构图更清晰。**不要照抄的部分**：让主聊天 LLM 用 function call 自管记忆——陪伴风格要"轻"，每 turn 多一次 tool reasoning 体感差。

#### Graphiti / Zep（实拉重点）

README 抓到的核心定义：

> A **context graph** is a temporal graph of entities, relationships, and facts — like *"Kendra loves Adidas shoes (as of March 2026)."* Each fact has a **validity window**: when it became true, and when (if ever) it was superseded. **Everything traces back to episodes — the raw data that produced it.**

四类组件：**Entities (nodes)** / **Facts (edges) with temporal validity windows** / **Episodes (provenance)** / **Custom Types via Pydantic**。

冲突处理原文：

> When information changes, old facts are **invalidated — not deleted**. Query what's true now, or what was true at any point in time.

检索：semantic + BM25 + graph traversal，sub-200ms。

**对 AIDemo 高价值借鉴点**：
1. **Episodes 概念是 AIDemo 缺的**——我们 `memories.value` 写入后丢了原始 turn 上下文，5.2 反验证只能凭 LLM 推断当时为啥这么写。如果加一张 `episodes` 表存原始 turn 片段 + episode_id 写到 memory 上，5.2/5.3 的 LLM 判断质量会跳一档，admin 排查也容易得多。
2. **validity window** 比我们 `status='stale'` 单 bit 更细致，能支持"用户曾经喜欢 X，现在喜欢 Y" 的叙事召回。
3. **Pydantic 定义实体类型** vs 我们 free-form `kind/key/value`：可以折中——保持 free-form，但对高频实体（人物/地点/爱好）加 entity 表 index。

#### Cognee

README 强调"control plane"定位：data ingestion + graph/vector + ontology + OTEL audit。**对 AIDemo**：单实例陪伴 bot 不需要 control plane；但 OTEL trace 思想可补——admin UI 现在的 audit 是 jsonl 平铺，trace_id 串联一次 turn 的 recall→LLM→write 链路，排查能跳一档。

#### LangMem（实拉重点）

README 明确两种 pattern：

> - 🧠 **Memory management tools** that agents can use to record and search information during active conversations **"in the hot path"**
> - ⚙️ **Background memory manager** that automatically extracts, consolidates, and updates agent knowledge

Hot path = LLM 自己调 `create_manage_memory_tool` / `create_search_memory_tool`；background = 自动 extract+consolidate。

**对 AIDemo**：术语借用——AIDemo 的同步 recall（turn 头）+ 5.2 反验证是"hot path"；flush 后 5.1/persona/feedback/Auto Dream 是"background"。这套命名直接抄进 `document/memory-stack.md` 章节标题就好。

## 二、纵向：研究论文要点

> 本节论文出处经训练语料确认，2026-Q1 后未实拉，链接为 arxiv 标准 URL，自查最新版。

### 几条贯穿性主题

1. **分层是共识**：episodic / semantic / procedural / working 这套分层来自认知科学，到 LLM agent 几乎所有正经实现都在用。AIDemo 已隐含分层（profile=semantic, event=episodic, prompt_overrides=procedural），但**缺一个 working/short-term 浓缩层**——`recent.json` 12 轮溢出后直接丢，没 summary。

2. **Reflection 巩固是分水岭**：[Generative Agents (Park et al., arXiv:2304.03442)](https://arxiv.org/abs/2304.03442) 提出当 importance 累积超阈值，触发 LLM 对最近 N 条记忆生成 3 个 top-level question 并据此生成更高阶 insight。AIDemo 的 Auto Dream 在这个谱系，但**只做清理不做生成**。

3. **召回评分三因子（Generative Agents）**：`score = α·rel + β·imp + γ·rec`。AIDemo 现在只有 cosine relevance + 双门过滤，没有显式 importance 和 recency decay。**Mem0 v3 走另一条路**——hybrid retrieval（semantic+BM25+entity）压过单纯三因子。两条路可以并行（recency 加权 + 多路召回融合），不冲突。

4. **知识冲突处理三个流派**：(a) ROME/MEND 类参数级编辑——不适用 LLM API 用户；(b) Mem0 v2/AIDemo PRD v2 的"语义比对+状态标记"——工程可行但有信息损失；(c) Graphiti bi-temporal 的"保留全部 + 验证窗"——叙事最完整。AIDemo 当前在 (b)，可选向 (c) 演化。

5. **Active retrieval（Self-RAG / FLARE 谱系）**：[Self-RAG (Asai et al., arXiv:2310.11511)](https://arxiv.org/abs/2310.11511) 让模型生成 reflection token 决定是否 retrieve / 是否采纳。AIDemo 是 turn 头一次 recall 拉到底，没有"reply 中段我需要再查一下"通道。

### 关键论文逐条（精简版）

- **MemGPT ([arXiv:2310.08560](https://arxiv.org/abs/2310.08560))**：OS 分页比喻 + agent function-call page in/out。启发：让主 LLM 在首次 recall distance 全部偏高时能调一次 `recall_more(query)` 二检（不必上 function-call，prompt 里给软指令即可）。

- **Generative Agents ([arXiv:2304.03442](https://arxiv.org/abs/2304.03442))**：memory stream + 三因子 + reflection 树。启发：三因子打分公式可移植；reflection 触发条件（importance 累积阈值）比 cron 更聪明，作为 cron Auto Dream 的补充而非替换。

- **Reflexion ([arXiv:2303.11366](https://arxiv.org/abs/2303.11366))**：失败后写 self-reflection 文本作为下次 prompt 增补。启发：feedback agent 已做"用户不满 → prompt_override"，对称加"用户正反馈 → reinforcement note"。

- **Self-RAG ([arXiv:2310.11511](https://arxiv.org/abs/2310.11511))**：模型输出 `[Retrieve]` `[IsRel]` `[IsSup]` reflection token。启发：不必训练，prompt 加一条"context 不足请输出 `<recall_again query=...>`"达到 70% 效果。

- **HippoRAG ([arXiv:2405.14831](https://arxiv.org/abs/2405.14831))**：PageRank-on-graph multi-hop 检索。启发：陪伴 multi-hop 不多，先不上；若引入 Graphiti entity 节点是天然下游。

- **EM-LLM ([arXiv:2407.09450](https://arxiv.org/abs/2407.09450))**：用 token-level surprise 自动切对话事件段。启发：固定 buffer 阈值 flush 太机械，可加"话题/情境是否切换"判定。

- **A-MEM ([arXiv:2502.12110](https://arxiv.org/abs/2502.12110))**：Agentic Memory，记忆条目互生 link 形成 Zettelkasten。启发：AIDemo 的 `depends_on` 已是 link 雏形，5.3 可顺手为新事实补 1-2 条 "related_to" 软链。

- **Zep paper ([arXiv:2501.13956](https://arxiv.org/abs/2501.13956))**：Graphiti 的理论基础，bi-temporal + episodes 范式。

- **Resolving Knowledge Conflicts ([arXiv:2305.13300](https://arxiv.org/abs/2305.13300))**：LLM 在冲突信息下倾向"更新"还是"坚持"取决于呈现方式。启发：5.2 反验证 prompt 加一句"如果两条都可能在不同时间为真，输出 still_valid 并标 valid_period"，避免错杀历史。

## 三、对 AIDemo 的可借鉴点（v2 重排版，按 ROI 排序）

### P0 强烈推荐（小改动，证据强）

1. **Hybrid retrieval：在 cosine 上加 BM25 + entity boost（Mem0 v3 实测最有效）**
   - 模块：`src/memory.py::recall`
   - 做法：(a) `memories` 表加 `pg_trgm` GIN index 或 `tsvector` 列做 BM25 候选；(b) 抽 entity 列表（人名/地名/爱好/物品）单独 index；query 走三路并行打分融合
   - 证据：Mem0 v3 LoCoMo +20、LongMemEval +27（实拉 README）
   - 收益：解决"那个我提过的播客叫啥来着"这种 cosine 抓不准的查询

2. **召回 ranker 加 recency decay + importance（Generative Agents 三因子）**
   - 模块：`src/memory.py::recall`
   - 做法：`score = (1 - dist) + α·log(confidence) + β·exp(-Δt/τ)`，τ 对 profile 设半年、event 设两周
   - 风险：与 P0-1 hybrid 同时上要打住 α/β/γ 调参陷阱，先 A/B 一个

3. **明确 hot path / background 命名（LangMem）+ procedural memory 命名（LangMem/Letta）**
   - 模块：仅文档 + admin UI tab 名
   - 做法：`document/memory-stack.md` 顶层划"hot path（同步 recall + 5.2）"和"background（5.1/persona/feedback/Auto Dream）"两章；admin "调教"tab 改名"Procedural Memory"
   - 收益：心智模型对外清晰，零代码风险

4. **Episodes 表做 provenance（Graphiti 核心借鉴）**
   - 模块：`src/memory_store.py` 新表 `episodes(id, user_id, raw_turns JSONB, ts)`，`memories` 加 `source_episode_id UUID`
   - 做法：每次 flush 把原始 buffer 存为一个 episode，抽出的 profile/event 都写 `source_episode_id`
   - 收益：5.2/5.3 LLM 判断时能看到原始上下文（不只是被抽出来的 NL fact），admin UI 可点条目跳到当时聊了啥
   - 工程量：1 张表 + flush 函数加 1 行；这是 v2 校准后**性价比最高的新增项**

### P1 值得评估（中等改动）

5. **bi-temporal 字段（Graphiti）**
   - `memories` 加 `valid_from / valid_to`，5.1 判 stale 时不删 status，写 `valid_to=now`
   - 收益：admin 可显示"用户曾经-现在"演化时间线，对陪伴 bot 是叙事金矿
   - 工程：schema + recall 过滤 + admin UI 渲染

6. **Auto Dream 加 insight 生成（Generative Agents reflection）**
   - 现 5.3 只清理 to_verify，加一步：每用户随机抽 N≈20 条 event+profile，让 LLM 写 1-3 条 `kind=insight` 高阶观察存回
   - 收益：陪伴感的"她真的懂我"靠的就是二阶事实

7. **Mid-term summary（Agno）+ episode 边界检测（EM-LLM 简化）**
   - recent.json 12 轮溢出前先 LLM summary 一句存 `data/session_summary/<uid>.jsonl`
   - flush 触发条件加"话题切换"判定，让 episode 更内聚

8. **召回二次检索（MemGPT/Self-RAG）**
   - 主 prompt 加软指令"context 不足请输出 `<recall_again query=...>`"，agent 层捕获并二检

### P2 长期方向

9. **OTEL trace 串联 turn 全链路（Cognee 思路简化版）**
10. **Pydantic entity 类型 + 轻量实体表（Graphiti 简化版）**
11. **Reflexion 正反馈对称沉淀（feedback agent 扩展）**

## 四、明确不借鉴 / 不适合

- ❌ **Mem0 v2 的 ADD/UPDATE/DELETE/NOOP 写入决策**（v3 已自我推翻；v1 草稿里我推荐过此条，**作废**）
- ❌ **Letta 全量 function-call 自改记忆**：陪伴风格要"轻"，主对话 LLM 拿到 archival_memory_insert 等工具会拉长 reasoning
- ❌ **纯图数据库（Neo4j-only）**：陪伴语境实体-关系密度低，pgvector 已够；Graphiti 借**字段**不借栈
- ❌ **Cognee 的 ontology-first 抽取**：陪伴话题极开放，预定义 ontology 徒劳
- ❌ **巨型 KV cache / 长上下文挤压记忆**：核心价值是"她记得三个月前"，靠 retrieval 而非 context 长度
- ❌ **multi-agent shared memory（CrewAI/AutoGen 类）**：单 agent + 单用户，shared memory 只会变 user 间隐私泄露面
- ❌ **continual fine-tuning / per-user LoRA**：维护 50 个 LoRA 不可行，与 OpenRouter 路径冲突
- ❌ **OpenAI/Anthropic 平台 memory tool**：闭源不可移植，仅作交互范式参考
